# RMS Authentication — Package Architecture

Ngày phân tích: 19/10/2026. Phạm vi đợt đầu: đăng nhập, đăng xuất, kiểm tra phiên; đăng ký ứng viên bằng OTP; khôi phục mật khẩu bằng OTP. Không bao gồm đổi mật khẩu trong hồ sơ, quản trị tài khoản/phòng ban hoặc các feature tuyển dụng khác.

## A. Architecture Summary

RMS là Spring Boot monolith tổ chức theo **package-by-feature**, với các thành phần dùng chung trong `core`. Authentication dùng Spring MVC, Thymeleaf, Spring Security form login và HTTP session. Trong package `auth` đã kiểm tra không có REST controller; không tạo thêm nhóm REST hoặc API service không tồn tại để khớp hình mẫu.

- **Login / logout / session:** `AuthController` hiển thị trang đăng nhập; Spring Security xử lý POST `/login` và `/logout`. `DatabaseUserDetailsService` đọc tài khoản theo username/email, ánh xạ role và trạng thái Active; `AccountSessionGuardFilter` đọc lại tài khoản để kết thúc phiên nếu tài khoản không còn hợp lệ hoặc authority thay đổi.
- **Registration OTP:** controller nhận form, `RegistrationVerificationService` kiểm tra identifier và điều phối OTP/session/email. Sau xác minh, `AccountManagementService` lưu tài khoản role Candidate cùng hồ sơ Candidate trong transaction.
- **Password Recovery OTP:** `PasswordRecoveryService` điều phối OTP, thời hạn và trạng thái phiên; `PasswordResetService` đọc/khóa tài khoản, kiểm tra snapshot và cập nhật password hash. Hai email sender dùng Spring Mail và template trong `auth/email`.

Presentation, Business, Data và Cross-Cutting trên sơ đồ là **nhóm kiến trúc logic**, không phải các package Java mới. Các ô ghi package là package thực tế; các tên lớp chỉ minh họa nội dung bên trong. Template, framework, HTTP session, SQL Server và SMTP là tài nguyên/hạ tầng, không phải package Java của RMS. Mũi tên nét đứt `A → B` chỉ sự phụ thuộc của A vào B; quan hệ chứa nhóm không đồng nghĩa dependency hoặc trình tự runtime.

## E. Architecture Observations

1. **Cycle trực tiếp ở cấp package:** `auth.exception → core.exception → auth.exception`. Exception feature kế thừa BaseBusinessException trong core, trong khi GlobalExceptionHandler trong core import và xử lý chính exception/DTO auth. Đây là coupling thực tế; không tự refactor trong đợt tài liệu này.
2. **Cycle tùy cấp độ gom nhóm:** ở cấp feature có `user → candidate → user`: AccountManagementService tạo Candidate, Candidate tham chiếu User. Ở cấp package chi tiết là chuỗi `user.service → candidate.entity → user.entity`, không phải cycle trực tiếp giữa `candidate.entity` và `user.entity`. Quan hệ User ↔ Department nằm trong cùng `user.entity`, không phải cycle giữa package; xem [User.java:49](../../src/main/java/com/group2/rms/user/entity/User.java#L49), [Department.java:36](../../src/main/java/com/group2/rms/user/entity/Department.java#L36).
3. **Core có phụ thuộc ngược feature:** GlobalExceptionHandler chứa kiến thức form/điều hướng auth. Ma trận module trong [ARCHITECTURE_GUIDE.md:53](ARCHITECTURE_GUIDE.md#L53) chưa thể hiện đầy đủ các cạnh ngược này; [mục hiện trạng:259](ARCHITECTURE_GUIDE.md#L259) đã ghi nhận handler đặc thù module. Dùng source hiện tại làm căn cứ cho sơ đồ, không coi ma trận rút gọn là đồ thị đầy đủ.
4. **Một package mang nhiều trách nhiệm kiến trúc:** `auth.service` chứa workflow, persistence service và email adapter; `auth.dto` chứa cả form công khai lẫn snapshot/prepared data nội bộ. Các ô tách theo vai trò trong sơ đồ là nhóm logic của lớp hiện có, không phải package mới. Controller chủ yếu điều phối form/validation/view; nghiệp vụ OTP và transaction nằm trong service.
5. **Comment đã lệch hành vi hiện tại:** Javadoc [PasswordResetService.java:20](../../src/main/java/com/group2/rms/auth/service/PasswordResetService.java#L20) còn mô tả signed email link, trong khi [PasswordRecoveryService.java:91](../../src/main/java/com/group2/rms/auth/service/PasswordRecoveryService.java#L91), [PasswordRecoveryService.java:107](../../src/main/java/com/group2/rms/auth/service/PasswordRecoveryService.java#L107), [PasswordRecoveryService.java:146](../../src/main/java/com/group2/rms/auth/service/PasswordRecoveryService.java#L146) triển khai OTP gắn HTTP session rồi cho đặt mật khẩu. Diagram mô tả code thực thi, không suy diễn JWT/token table từ comment.
6. **Giới hạn suy luận:** state OTP đặt trong HttpSession và cooldown map của service, được xác nhận bằng source; chưa xác minh session store, nhiều instance hoặc restart ở môi trường triển khai. Session guard hiện so sánh tài khoản/Active/authority; không mô tả nó như cơ chế phát hiện mọi thay đổi tài khoản. Các nhận xét này là quan sát kiến trúc tĩnh, chưa phải kết luận lỗi runtime.
